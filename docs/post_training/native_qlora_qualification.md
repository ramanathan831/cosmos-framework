# Native QLoRA qualification checklist

**The native QLoRA path is implemented and experimentally measured, but it is not release-qualified.** The existing trained NF4 model's supervised-token NLL was 4.18% higher than the matched BF16 control on the exposed WTS diagnostic, exceeding the unchanged 2% margin. A subsequent data audit also found related recording families across the original training and validation splits. Neither faster preprocessing nor new configuration acceptance resolves these quality requirements.

The completed continuation checklist below reviews implementation commit `55e7f14dfeca84002d0324108808a0e682579842`; the ongoing improvement section records subsequent native changes and their separate evidence. Historical full-training evidence belongs to the earlier sealed `c5b8d49` and `a406ea1` runtimes. The [continuation kernel gate](evidence/native_qlora_kernel_gate_55e7f14.json) passed all 14 CUDA cases and the existing higher-precision native CPU regression for the exact `55e7f14` wheel, without skips. All eight development experiments have their own [completed training and evaluation evidence](evidence/native_qlora_development_candidates_55e7f14.json). The controlled and selected three-seed comparisons and workload-specific recovery results are recorded below; historical evidence does not automatically qualify a new build. See the [native training guide](native_qlora.md), [original design](qlora_native_vlm_design.md), and [qualification tool instructions](../../tools/native_qlora_qualification/README.md).

The [continuation audit evidence](evidence/native_qlora_qualification_audit_20261030.json) records the four-arm reanalysis, per-example differences and uncertainty, source metadata and split audit, sealed experiment criteria, and completed CPU workload shapes. It does not claim completion of the new GPU runs.

The [new build-preservation check](evidence/native_qlora_cross_build_55e7f14.json) reproduced the archived four-update NF4 and BF16 states from fresh training with the original inputs. Adapter and optimizer payloads, trainer state and data cursor were byte-identical. DCP index serialization differed, while decoded entries matched; model metadata differed only in the two declared code/wheel identity fields. This qualifies the timing counters for that diagnostic trajectory. It does not establish a new 300-update result or permit cross-build production resume.

The [completed development lifecycle checks](evidence/native_qlora_development_lifecycles_55e7f14.json) cover all eight seed 42 settings: both precision arms at rank 16/alpha 32 with learning rates `5e-5`, `1e-4` and `2e-4`, plus rank 32/alpha 64 at `1e-4`. The separate [completed long-sequence recovery evidence](evidence/native_qlora_long_recovery_55e7f14.json) extends those correctness checks to the prepared `long4k_video8` workload at rank 16/alpha 32, microbatch one with accumulation eight and full activation checkpointing. It does not repair the original long-workload host-memory gaps, qualify a memory budget, establish WTS task quality or demonstrate recovery at update 20 or 300. The long targets are synthetic text paired with real video.
